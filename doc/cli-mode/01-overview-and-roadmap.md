# 模块 01：总体方案与实施顺序

## 1. 模块目标

本模块用于回答三个问题：

- CLI 模式第一版到底做到什么程度
- 哪些内容必须先做，哪些可以后做
- 后续开发如何分阶段推进，避免返工

## 2. v1 范围

CLI v1 建议只覆盖以下内容：

- 新增 `n9e-mcp-server cli` 子命令
- 继续兼容 `N9E_TOKEN`、`N9E_BASE_URL`
- 实现共享业务层 `pkg/app`
- 实现首批只读命令
- 实现 `mutes create/update`
- 实现统一的 `json` 输出
- 为高频 list 命令预留 `table` 输出

不建议在 v1 一次性做完的内容：

- 所有命令都支持漂亮表格
- 复杂交互式表单
- 批量操作
- shell completion
- 高级配置文件体系

## 3. 非目标

本阶段不建议触碰以下内容：

- 改变根命令默认行为
- 改变现有 MCP tool 名称或 schema
- 重写 `pkg/client`
- 改 npm 包行为
- 引入过重的命令插件化框架

## 4. 推荐阶段拆分

### 阶段 A：铺底座

内容：

- 统一配置入口
- 抽出 `pkg/app`
- 新建 CLI 命令骨架

判定标准：

- CLI 可以启动
- CLI 可以复用环境变量认证
- MCP 行为不变

### 阶段 B：首批只读命令

内容：

- `busi-groups list`
- `alerts active list`
- `alerts active get`
- `targets list`
- `users list`
- `mutes list`

判定标准：

- 至少覆盖列表、详情、筛选、分页四类模式

### 阶段 C：写命令

内容：

- `mutes create`
- `mutes update`

判定标准：

- 写命令受 `--read-only` 约束
- 可通过 `--yes` 跳过确认

### 阶段 D：体验与质量收口

内容：

- `table` 输出
- 错误信息优化
- 单元测试与集成测试
- README 更新

## 5. 模块依赖

本模块是其他模块的前置文档。

依赖关系：

- 模块 02、03、04 都依赖本模块确定的边界
- 模块 05、06 的范围由本模块控制
- 模块 07 的验收标准也应以本模块为准

## 6. 建议交付物

开发前建议达成以下共识：

- v1 命令清单
- 目录结构方向
- 首批命令的优先级
- 不在 v1 范围内的事项列表

## 7. 建议实施顺序

推荐顺序：

1. 模块 02
2. 模块 03
3. 模块 04
4. 模块 05
5. 模块 06
6. 模块 07

## 8. 验收标准

- 团队对 CLI v1 范围没有歧义
- 每个开发模块有明确输入和输出
- 后续编码能按模块排期，而不是按零散需求推进
